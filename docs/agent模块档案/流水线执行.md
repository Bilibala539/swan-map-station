## 1. 一句话职责

负责流水线任务(pipeline_jobs)的触发/派发/认领/收尾全链路 + 执行 agent(scripts/pipeline_agent.py)轮询与 Jenkins 定向执行 + 设备池调度(devices 表 + conftest 会话级自动领取/归还),让平台接到的每个任务都真正落成一次执行会话(run)。M3 起:任务建完优先派 Jenkins 构建(swan-autotest,master@.167:8082+agent@.176,参数 JOB_ID),派发失败留 pending 由本地 PipelineAgent 兜底。

## 6. 关键业务规则与坑

1. **claim 原子性**:定向=SELECT 该 job 是否 pending,轮询=SELECT 最早 pending 且 jenkins_job 为空;统一 `UPDATE ... WHERE job_id=? AND status='pending'`(server.py:1198-1200),单机事务防多 agent 抢跑;改这块必须保持 WHERE status='pending'。惰性抢回在**独立事务**先行(server.py:1176-1177)——不能与 claim 同事务:无 pending 时 LookupError 会回滚同事务里的抢回结果(transaction() 异常即 close 未 commit 连接=隐式回滚)。
2. **finish 状态枚举校验**(server.py:1207-1209),非法状态 400。
3. **门禁 rc3=env_blocked**:PREFLIGHT=1 下 conftest 会话门禁失败 pytest.exit(3)(conftest.py:104-113)——绕过 sessionfinish 上报,run 会永远停留 running,所以 agent 补一条 POST /api/runs/<run_id>/complete status=error 收尾(pipeline_agent.py:123-134),保证执行会话/流水线状态一致。env_blocked 不重跑、不计失败(环境问题按 bug 处理)。
4. **门禁重试**:pytest rc=1(有用例失败)→ 自动 `--lf` 只重跑失败项一次,重跑通过=succeeded(rc=1 时不重跑→failed);rc=0→succeeded;其他非零(收集/用法错误)→ error 不重跑(pipeline_agent.py:348-375)。**--lf 重跑是新 pytest 进程,conftest 会重新 acquire 设备——这就是任务级"拔线重排"通道(换台好设备),无需额外机制**。
5. **run_id = `pipe-<job_id>`**(pipeline_agent.py:351),经 DASHBOARD_RUN_ID 贯穿 conftest 设备领取与执行会话上报——这是任务↔执行会话的关联键。
6. **pythonw 无 stdout**:常驻计划任务下 sys.stdout=None,pytest 子进程必须重定向 output/logs/pipeline_<run_id>.log,**追加模式 + attempt 分隔行**(pipeline_agent.py:110-121),--lf 重跑不覆盖第一轮现场。server 侧超时抢回同理写独立文件 logs/pipeline_reaper.log(_reap_log server.py:134)。同理运行面纪律(.167/.176 通用):绝不 kill 全部进程,只杀指定 PID。
7. **公平分配**:acquire 按 (prefer 优先, last_assigned_at 空值最前) 排序取首(_rank server.py:1040 附近),领取时原子 `UPDATE ... WHERE status='online_idle'` 防并发双领(:1047-1052)。
8. **busy 4h 自愈 + 拔线重排三件套**:acquire 无空闲时把 busy_since 超 4h 的同平台设备回收为 idle 再找(server.py:1025-1031;_stale_cutoff server.py:116-119,4h 写死)——兜底。主动重排由三处协同:① device_pool.release 归还前 adb 复核,失联设备置 offline 而非 idle(device_pool.py:114-127);② set_device_status 放宽 busy→offline 并清 current_run/busy_since(server.py:1085-1093);③ register 对 offline 设备复活回 idle 并清 run 占用(server.py:972-980)。效果:拔线设备不再被误领,重插即复活。
9. **register 幂等**:已存在设备的重复注册只刷新心跳/元数据;busy/disabled 状态及 run 占用完全不覆盖(server.py:950-961);offline 复活见规则 8③;新设备 INSERT :936-948。
10. **503=无设备**:acquire 503 → conftest pytest.exit(3) 转环境阻塞,不算用例失败。
11. **running 超时抢回**:running 且 claimed_at 超 RUNNING_TIMEOUT_HOURS(常量 server.py:125,默认 1h,环境变量可覆盖;依据:实测单 job 全程最长约 2 分钟,1h≈45 倍余量,远小于设备 4h 自愈)→ 标 error+finished_at+result_json{reaped:true,...},同事务释放其占用设备,写 logs/pipeline_reaper.log(_reap_timeout_jobs server.py:176 起)。触发时机=claim 前惰性回收,UPDATE 带状态条件,幂等。**注意:不处理 runs 会话收尾(runs 归执行与证据模块)**。
12. **apk_id 透传**:_run_pytest 把 job.apk_id 写入 SWAN_APK_ID 传给 pytest 子进程(pytest_plugin 读它落 runs.apk_id);job 未指定时主动 env.pop 清外层残留,保证 run 包关联严格等于任务指定,并且同分支写入 SWAN_PACKAGE(=SWAN_PACKAGE 环境变量,缺省 com.swan.network)驱动 preflight 的 app_installed 检查。
13. **装包环节(2026-09-22)**:execute_job 在 pytest 前调 ensure_apk_installed(pipeline_agent.py:307;下载 :176/_install_apk :252/_pick_confirm_tap :224)——job 带 apk_id 时:平台 /api/apks/<id>/download(两级回退,跨机安全)下载到 output/apk_cache/<id>.apk(有缓存复用)→ 对每台在线设备查 `pm list packages` + 设备侧标记 /data/local/tmp/swan_installed_apk_id.txt;**包已装且标记=任务 apk_id 才跳过,否则 install -r 重装**(新构建包变更自动换包;大包 1-3 分钟,install 超时 1800s)→ 成功后写标记。**荣耀/小米等厂商装包会弹确认框(荣耀两道屏:来历不明对话框→安全审核页需先勾风险框),_install_apk 在 install 进程存活期间按 _pick_confirm_tap 规则表逐屏自动点通(先勾 checkbox 类、后点正向按钮、排除 取消/应用市场/广告位;只认控件属性与文字,不写坐标;新机型确认路径不同=往规则表加一条)。AOSP verifier settings 关闭无效(实测),别再试);装完收尾页(完成/打开)只点 完成(不代点 打开),页面不认识回 HOME。**任一设备失败或下载失败 → _finish_env_blocked(env_blocked 语义,不重跑不计用例失败);无 apk_id 任务直接跳过,零开销。
14. **Jenkins 派发(M3)**:trigger/config-run 建完任务 → try_jenkins_dispatch(server.py:142)→ Jenkins trigger(swan-autotest,参数 JOB_ID)→ 成功:mark_jenkins_dispatch(:1235)回填 jenkins_job + 短轮询队列(最多 3 次×1s)拿 build 号,拿不到只记 result_json.jenkins_queue_id;**失败:jenkins_job 保持空串 + result_json.jenkins_trigger_failed,任务留 pending 本地兜底**。未配凭据静默走本地(本地开发机无痛)。派发日志 logs/jenkins_dispatch.log。
15. **claim 双通道(M3)**:payload 带 job_id=定向认领(原子保留;不可认领 404→agent 空跑退出);不带=轮询(WHERE pending AND (jenkins_job='' OR IS NULL) ORDER BY created_at LIMIT 1,server.py:1190-1192)——跳过已派发的,否则本地 agent 抢在 Jenkins 构建启动前会让构建空跑。**残留风险:Jenkins 201 后崩溃则该 pending 任务需人工重触发**(轮询不会接管它);并发构建=多 agent 进程各领各的设备,设备池天然支持。
15. **Jenkins 凭据纪律**:只在 .167 /opt/uiautotest/.env.local(JENKINS_BASE_URL=http://127.0.0.1:8082/JENKINS_USER/JENKINS_API_TOKEN);本地自测用 mock server+环境变量指假端点,**禁止从本机碰运行面 Jenkins**。
16. **打包→冒烟联动(M5)**:打包成功 → Jenkins batch 调 trigger_smoke.py(--suite/--apk-id)→ 套件成员聚合 case_filter(GET /api/suites/<id>/case-paths;**YAML 驱动用例已映射 node id**——list_suite_case_paths server.py:1934 对 knowledge/swan/cases/driver/*.yaml 生成 `tests/flutter/test_case_driver.py::TestCaseDriver::test_yaml_<stem>`(子目录同样按 stem),其余路径原样;非 driver 目录的 YAML 跳过;run_pipeline_config 聚合同源不再按 .py 过滤)→ POST trigger(trigger_source=build-downstream)→ 复用 try_jenkins_dispatch 派 swan-autotest。**防环:平台 JENKINS_TEST_JOB 必须只指向测试 job**;冒烟触发不会再触发打包(swan-autotest 构建只跑 agent --job-id)。脚本报错语义:套件不存在/无脚本成员 exit 2(明确 stderr),网络错 exit 1,成功 0。
