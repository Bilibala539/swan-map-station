## 1. 一句话职责
记录每次自动化执行(run)与每条用例结果(case),提供会话列表/详情与用例历史查询、失败证据留存策略,并把失败用例半自动提单到禅道(人工确认后才提交)。

## 2. 数据表(DDL: dashboard/server.py:575 起;行号快照 2026-09-22 晚,漂移后以 grep 符号为准)
| 表 | 字段 | 说明 |
|---|---|---|
| runs | run_id PK, platform, status(默认 running), app_version, device, jenkins_build, started_at, ended_at, duration_seconds, total/passed/failed/skipped/error_cases, metadata_json, zentao_task_id(591); apk_id/zentao_task_id 老库轻量迁移补列(initialize 内 PRAGMA 检查段) | 一次执行会话 |
| cases | (run_id, case_id) 联合 PK, name, platform, status, started_at/ended_at, duration_seconds, log, error, artifacts_json; FK→runs ON DELETE CASCADE(593-607) | 一条用例结果,case_id=pytest nodeid |
| 索引 | idx_runs_started_at / idx_cases_run_id / idx_cases_case_id(cases DDL 之后紧随) | |

状态机:
- runs: 创建即 running(create_run 817,INSERT 默认 'running')→ complete_run 归一定终态(server.py:916-925):上报 passed 但存在 failed/error 强制改 failed;非法值按有无失败兜底。**cancelled/cancel 上报直定为独立终态 cancelled(2026-09-22 M-B2):不走 normalize_status 别名归一、不做 passed→failed 覆盖,取消前已上报用例计数如实保留**。
- **孤儿收尾**(2026-09-20 加,_sweep_orphan_runs:939):run 卡 running 而关联 pipeline job 已终态(PIPELINE_JOB_FINISHED_STATUSES=succeeded/failed/env_blocked/error/cancelled,含 reaped 抢回)→ get_run/list_runs 查询路径惰性代管收尾(幂等,get_run 内 1531 调用)。关联键=执行 agent 的 run_id 约定 pipe-{job_id}(pipeline_agent.py:124)前缀反查,不依赖 job 侧;ended_at 取 job.finished_at,状态口径:job succeeded 且有用例→按 cases 聚合(对齐 complete_run);**job cancelled→run 定 cancelled(M-B2,reason 区分平台强制取消 forced_cancel)**;失败/抢回/无用例→error;reaped 等写 metadata_json.orphan_swept(job_id/job_status/reaped/reason/swept_at),日志 logs/runs_sweeper.log。
- cases: normalize_status 别名归一(server.py:89):pass/success→passed、fail→failed、skip→skipped、broken→error,未知→error。cancelled 不进该归一(cases 无取消概念,仅 run 层有)。
- pass_rate 不落库,serialize_run 现算(server.py:1505)。

## 6. 关键业务规则与坑
- **提单不可逆(硬纪律)**:/api/zentao/create 缺 confirm 字段直接 400;页面必须经 bug-modal 人工确认(页面侧 confirm:true 在 bug-submit 884);任何脚本/自动化禁止绕过弹窗直接 POST create。环境缺陷(网关不通/设备掉线)不建业务 bug 单(zentao_client.py:13-14)。
- **孤儿收尾关联契约**:runs 侧靠 run_id `pipe-{job_id}` 前缀反查 pipeline job——这是与 pipeline_agent 的隐式契约,若执行 agent 改 run_id 约定须同步改 _sweep_orphan_runs(两侧都要动)。手工 pytest 会话(pytest-* 前缀)不受影响。
- **禅道测试单回写(M6,2026-09-20)**:REST v1 无用例级回写端点(/testruns、/testtasks/{id}/testruns 均 404),结果以汇总 HTML 写进 testtask desc。runs.zentao_task_id 列(DDL 468+PRAGMA 迁移 490-495)存单号:空→POST /testtasks 建单并回存,非空→PUT /testtasks/{id} 更新 desc(重复点击=更新同一单,幂等)。project/product 读 env ZENTAO_PROJECT_ID/ZENTAO_PRODUCT_ID(.env.local),未配置 400;running 409(RunNotFinalizedError);禅道错 502。build 取 run.jenkins_build 否则 "trunk"——禅道 build 若要求产品内合法 build id,trunk 兜底是否被 22.1 接受待真实回写验证。desc 用例清单超 50 条截断。zentao_client 新增 create_testtask(107)/update_testtask(124)。**人工确认纪律:仅页面"回写禅道测试单"按钮触发,禁止任何自动回写**。
- 禅道凭据只在部署机 .env.local(ZENTAO_URL/ACCOUNT/PASSWORD/PROJECT_ID/PRODUCT_ID),不进 git;URL http://8.129.106.82:9000/zentao,产品 7=Swan Audio Flutter;REST v1 tokens→products→bugs,create_bug 默认 keywords="自动化"、type=codeerror(zentao_client.py:84-101)。
- **已取消状态(M-B2,2026-09-22 交付)**:runs 第六个状态值 cancelled,语义=任务被取消(取消≠执行结论)。入口唯一:执行 agent 取消 pytest 后 POST complete(status=cancelled)——pipeline_agent.py:216 RUN_COMPLETE_STATUS_ON_CANCEL 由主会话统一切 "cancelled"。配套:①统计卡平均通过率分母排除 cancelled(page.html:802);②孤儿收尾 job cancelled→run cancelled(server.py:939 内分支);③**cancelled 回写禅道 → 409(拍板:会话无结论可写,要结果就重跑;sync_run_zentao 入口 raise RunNotFinalizedError,页面按钮同步隐藏 822)**;status_cn 保留"已取消"映射(防御性,政策若变即用);④badge 中性灰 --muted/--neutral-weak(规范 2.2/6.3)。页面无取消入口,取消只在流水线任务列表发起。
- 建单链路:失败用例→openBugDraft(859;先查 /api/zentao/config 缓存 zentaoConfigured,未配置 toast 拦截 860-864)→POST draft(标题 `[Swan][模块] 用例名 自动化失败(run_id)`,steps 含复现步骤+日志尾 1500 字+证据截图目录,zentao_draft 2774)→弹窗人工修改→POST create(confirm:true);产品 ID 记 localStorage('bug-product')(871/881)。
- **快照规则**:cases 行是执行时快照(case_id=当时 pytest nodeid;artifacts_json 存当时的 apk_id/jenkins_build/evidence_dir);case_defs 后续改名/编辑**不回写**历史记录;查历史时包/设备从所属 run 行 JOIN 取(get_case_history 1656-1671)。runs 是 upsert,同 run_id 重跑会覆盖 apk_id 等并重置 running(832-838)。
- /api/cases/search 空 q 返回全部是明确需求(未搜索先展示全部,server.py:1673)。
- 自测纪律:禅道改动用 monkeypatch 拦 `zentao_client._request`(43)验证 payload,绝不真建单;本地临时端口起 server 冒烟。

## 7. 模块边界
- 流水线执行(pipeline_agent/设备池):执行 agent 跑 pytest,run/case 记录由本模块 pytest_plugin 上报产生;pipeline_jobs 状态流转归其模块,结果展示落本模块页面。
- 包管理:runs.apk_id↔apks 表关联;page-apks 原"查看执行"按钮已移除,包体筛选下拉仍由 /api/apks 填充(本模块 loadApks)。
- 用例管理(case_defs):cases.case_id 与 case_defs.case_id 同键空间(nodeid);历史页↔用例定义页互跳;改定义不回写历史(见快照规则)。
- 套件/流水线调度:套件执行的 run 走同一上报链路,但 runs 无 suite_id 字段,套件维度历史暂查不了。
