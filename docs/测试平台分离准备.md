# 测试平台分离准备(2026-10-13)

> 背景与目标(用户拍板):测试平台代码从自动化工程(E:\UIAutotest)剥离出去,与工作站代码放一起——形成独立的服务端仓库。
> 本文档是分离前的盘点与方案:资产清单、耦合点、目标形态、步骤草案、拍板项。**尚未执行任何分离动作。**

## 1. 依赖面侦察结论(2026-10-13 实测,分离的有利条件)

1. **dashboard 全家零第三方依赖**:`dashboard/server.py` 纯标准库(http.server/sqlite3/urllib/hmac),HTTP 全走 urllib.request;`workstation/serve.py` 同理。新仓库 requirements 几乎为空(仅 dashboard/tests 需要 pytest)
2. **根 requirements.txt 无平台专属条目**(selenium/pytest/opencv/paddleocr 全是自动化侧)——不需要拆
3. **`dashboard/client.py` 只被 `dashboard/pytest_plugin.py` 引用**(server.py 都不用它)——上报对与平台服务端无耦合
4. **pytest.ini / run_parallel.py 无 dashboard 引用**;自动化侧对 dashboard 的引用只有一处:`conftest.py:20` `pytest_plugins = ["dashboard.pytest_plugin"]`
5. **运行面早已物理分离**:.167 `/opt/uiautotest`(平台部署+sqlite3)/ `/opt/app`(工作站);.176 Jenkins 跑自动化。仓库分离不动运行面数据
