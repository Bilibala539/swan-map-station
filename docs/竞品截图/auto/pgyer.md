# 竞品采集：蒲公英（pgyer.cn）

> 采集 2026-09-20，design_shot.py（viewport.png / fullpage.png / styles.json 同目录，样本为营销首页）。
> **应用详情/下载页在登录墙内，无法自动采集**——下方形态画像凭公开产品形态与行业共识整理，供参考；精确样式需人工截图后补充（放 docs/竞品截图/pgyer/）。
> 关注点：二维码呈现、下载按钮形态（App 分发赛道直系对标）。

## 首页结构（实测截图）

- 定位文案"应用内测分发平台"，核心流程一句话："上传 App，快速生成下载链接和二维码。既可用于研发团队内测，也可用于渠道交付、智能硬件配套 App 下载和长期版本更新。"
- 主色青绿 rgb(26,188,156)；导航：内测分发 / 获取 UDID / 价格 / 文档；右侧登录/注册。
- 长图其余为服务体系/全球服务/安全承诺等营销内容，无产品界面演示。

## 应用下载页形态画像（登录墙内，凭公开共识）

- 左栏：应用图标 + 名称 + 版本/大小/更新时间等元信息竖排列表 + 更新说明。
- 右栏固定：**大号"安装"实底按钮**（按访问设备平台自动切 iOS/Android 文案）+ **二维码**（扫码直接下载，页面第一视觉锚点）+ 可选密码保护提示。
- 版本历史：每个 App 独立的历史版本页，逐版列出更新说明与时间。

## 四项关注点比对

| 关注点 | 蒲公英的做法 |
|---|---|
| 下载按钮形态 | 大实底"安装"按钮，**按访问设备平台自动识别**切换文案与产物 |
| 二维码呈现 | 应用页主视觉，右栏常驻，扫码即下——二维码是分发页第一公民 |
| 正式/测试环境分类 | 无服别概念——按 App 分组（一个应用一页），渠道靠多 App/渠道号实现 |
| 版本列表信息密度 | 每 App 独立历史页，非单页长列表 |

## 可借鉴点

1. **二维码常驻主视觉**：与 GitHub（无码）形成两极，App 分发赛道一致选择"码即入口"。我们双卡直出 160px 码的决策与此互证。
2. 按平台自动识别安装按钮：我们已裁决不做 UA 检测（单平台产物），弹窗静态文案覆盖同等预期——**维持原裁决**，其体验差异仅在多平台产物时出现。
3. 密码保护：内网工具不需要，不借鉴。

## 对本平台下包页的建议

- **无设计改动**。最大收获是验证：App 分发场景下"二维码+大按钮"右栏常驻是业界共识形态，我们卡片内嵌码+Primary 下载同构。
- 服别分类（server_type）在分发平台无现成对标（它们按 App 分组回避了这个问题）——我们的 formal/test 是自有设计，无业界惯例约束，放心沿用。
