# 竞品采集：GitHub Releases

> 采集 2026-09-20，design_shot.py（viewport.png / fullpage.png / styles.json 同目录）。
> 样本：pyinstaller/pyinstaller 的 releases 列表页（公开，版本多、资产多）。
> 关注点：版本列表信息密度（本项目核心对标维度，规范七"Nexus Latest"之外的第二个样本）。

## 页面结构

- **左侧 Release list**：版本号锚点列表（v6.22.3 → v6.16.0），滚动时当前视口对应条目高亮（左侧竖条指示）；底部 Previous/Next 翻页。
- **右侧 release 卡片流**（时间线式，每版本一张卡）：
  - 版本号大字（v6.22.3）+ **Latest 绿色胶囊**（只打最新一条）+ 右上 Compare 下拉；
  - meta 行：发布者头像+用户名 · "released this last week"（相对时间）· tag chip（v6.22.3）· commit 短 sha（**等宽字体**）；
  - 正文：changelog 链接一段；
  - **Assets 折叠区**：`▼ Assets 2` 展开（仅当前最新/被点击的条目），历史条目 `▶ Assets 2` 收起。展开后每资产一行：图标 + 名称蓝色链接（Source code (zip)）+ 右侧相对时间。
- **底部数字分页**：Previous · 1 2 3 4 5 … 8 · Next（每页 10 条）。
- 已验证签名的 commit sha 旁带绿色小勾（可信度标记）。

## 四项关注点比对

| 关注点 | GitHub 的做法 |
|---|---|
| 下载按钮形态 | 无按钮——资产名称即蓝色文字链接，行尾相对时间；命名即文件名 |
| 二维码呈现 | 无（开源仓库场景不需要） |
| 正式/测试环境分类 | 无（开源发布无此概念） |
| 版本列表信息密度 | 高：锚点列表 + 卡片流双层；**最新条目默认展开、历史全部折叠**，一屏 10 个版本无压迫感 |

## 可借鉴点

1. **"最新展开、历史折叠"的密度分层**——信息密度管理的标杆手法。与我们下包页"双卡（最新）+ 全量表格"同构，互证该方向。
2. **Latest 标唯一性**：全页只有最新一条带 Latest 徽章，锚点清晰。规范 6.2 包管理"最新"小标与 Nexus 对标一致，此为第二样本。
3. 相对时间为主文案 + commit sha 等宽——与本规范 5.4/3.2 已定规则一致，无需改动。

## 对本平台下包页的建议

- 现设计（最新可用双卡 + 全量表格）已覆盖其核心价值，**无需改设计**。
- P2 备选：若未来包数量上百且需要按版本号快速跳转，可参考左侧锚点列表；当前 200 条限内收益低，不做。
- 下载次数/资产热度 GitHub 不展示（react 等热门仓库才有），我们不缺这个维度，P1 下载统计列维持原计划。
