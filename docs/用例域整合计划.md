## 1. 现状事实(2026-10-13 实地侦察,全部实测)

### 1.1 Swan 功能地图工作站(:8090,`/opt/app`)
- **无数据库**:用例正文 = **版本化编译产物** `data/versions/0.3.0/cases.json`(1060 条,2.5MB),由 `tools/build_data.py` 从上游源 `F:\SwanApp-Toolchain\docs\qa-knowledge` 编译(编号终身制注册表 `registry/ids.json`)
- **人审状态独立存储**(用户可写数据):`data/review/decisions-<版本>.json`(status/reason/reviewer/decidedAt + 两道门 gates)+ 追加式 `audit.jsonl`。当前仅 4 条裁决,**1060 条全部 pending**
- `serve.py` 428 行纯标准库(ThreadingHTTPServer + JSON 文件);POST 仅人审三件套(`/api/review/gate|decision|batch`,reviewer 必填、两道门 view 强制、审计追加);**用例正文无写 API**
- `/api/review/cases` = cases.json(正文) + decisions(人审) **运行时合并**;`GET /api/review/state` 轻量返回人审状态
- 部署:jks 用户手动进程(非 systemd),`python3 serve.py --host 0.0.0.0 --port 8090`

- `dashboard/case_api_client.py`:工作站拉取管线已建(fetch→normalize→upsert,幂等、formerId 重锚、human_confirmed 映射),**从未实际运行过**
- 自动化用例:`tests/flutter/test_*.py` 32 个文件(一用例一文件),docstring 内散写"回归用例 N"锚点;pytest 上报 case_id=nodeid(`dashboard/pytest_plugin.py:65`)

## 2. 目标架构:一库两服务(2026-10-13 用户拍板:真共库)

```
唯一数据库:/opt/uiautotest/output/dashboard.sqlite3(case_defs 表)
  ├── 测试平台 :8080(dashboard/server.py)——现状已连,用例 CRUD/套件/执行历史
  └── 工作站  :8090(serve.py 改造)——直连同一库:
        · 展示:case_defs.structured 还原 cases/0.3 报文 + review_meta 人审态(前端零改动)
        · 人审:POST 三件套直接 UPDATE case_defs.review_meta(decisions.json 退役)
        · 增删改:工作站侧用例 CRUD API(写同一张表)
```

- **只有这一个数据库**。两边展示/读写的都是同一行数据,一边写另一边立即可见
- 人审状态不再存文件:case_defs 加 `review_meta` JSON 列(status/reason/note/reviewer/decidedAt/gates),
  `human_confirmed` 列作为 status=stored 的冗余投影(SQL 可过滤);`decisions.json`/`cases.json` 编译产物退役归档
- 并发:SQLite WAL + busy_timeout;用例操作是低频人工写,足够;将来量大换 PostgreSQL 只改连接层
- 工作站"版本化编译"(build_data.py→versions/)对**用例正文**退役;功能地图/矩阵/缺陷等其余产物不受影响

- 迁移幂等(upsert),重跑安全;两平台同机(127.0.0.1 互通),无跨机依赖
